Caveats that catch people


    

  • Config lives in ROMMON. stackwise-virtual link and stackwise-virtual dual-active-detection are stored in ROMMON variables and the running config, not the startup config. The DAD command does not even appear in show running-config after it is applied.
    • 

  • Recovery-reload-disable is not persistent. dual-active recovery-reload-disable is saved only to the running config, so plan for it to be gone after a reload.
    • 

  • Normal shut/no shut is blocked on SVL and DAD ports. Cisco's troubleshooting note uses test platform software nif_mgr port disable for lab tests only.
    • 

  • Early recovery mode. A switch can enter recovery mode with some SVL members still cabled if links flap or LMP/SDP exchanges fail. Partially seated transceivers are a known cause.
    • 

  • Management port conflict. The guide says management interfaces stay up in recovery mode; the white paper log shows Gi0/0 going down. Keep console access to both members.
    • 

  • ePAgP has hard dependencies. PAgP desirable MEC, a member on each switch, an ePAgP-capable Cisco neighbor and stack-mac persistent timer 0. LACP or mode on gives no detection.
    • 

  • SPAN cannot use SVL or Fast Hello DAD ports as source or destination.
    • 

  • Private VLANs: set the native VLAN on isolated trunk ports explicitly.
    • 

  • Custom SVI MACs: if one SVI or routed port uses mac-address and needs Layer 3 injected packets, all others must share the same first four bytes.
    • 

  • Multicast: carry it on MECs rather than ECMP so a switchover doesn't change multicast routes.
    • 

  • CLI or NETCONF replace of SVL settings lands in the CONFD database and only shows in IOSd after write memory and reload.
    •

Configuration reference






Design rules from the sources


    

  • Build the SVL from at least two members, spread across ASICs and separate physical paths. A single member failing costs roughly 50–100 ms for flows hashed onto it; only losing the last member splits the pair.
    • 

  • Never use the same port for SVL and DAD. On C9500 the SVL and DAD configuration needs a reload to take effect (C9500X adds and removes links live).
    • 

  • Run both DAD methods where you can. Cisco states Fast Hello and ePAgP can be deployed together for higher resiliency.
    • 

  • ePAgP needs a PAgP MEC (mode desirable) with at least one member on each switch, terminating on a Cisco switch that supports ePAgP. An LACP MEC gives no dual-active detection.
    • 

  • Set stack-mac persistent timer 0 so the stack MAC never changes on switchover; Cisco requires it for ePAgP to work without PAgP flaps.
    • 

  • Dual-home everything with MEC. Single-homed ports force traffic across the SVL and lose service entirely if their switch goes into recovery.
    • 

  • Keep console or out-of-band access to both members. The switch in recovery mode shuts its front-panel ports, and the white paper's sample log also shows its management port Gi0/0 going down.
    •

Abbreviations




SVL
StackWise Virtual Link, the inter-chassis EtherChannel carrying control and data


DAD
Dual-Active Detection, finds a split where both switches think they are active


SSO
Stateful Switchover, the hot-standby takeover model


NSF
Nonstop Forwarding, keeps hardware forwarding during switchover


MEC
Multichassis EtherChannel, one port-channel with members on both switches


LACP
Link Aggregation Control Protocol (IEEE 802.3ad)


PAgP
Port Aggregation Protocol, Cisco's EtherChannel negotiation protocol


ePAgP
Enhanced PAgP, adds a TLV carrying the active switch ID


TLV
Type-Length-Value field inside a protocol message


LMP
Link Management Protocol, per-member SVL health and integrity


SDP
StackWise Discovery Protocol, resolves active and standby roles


SVH
StackWise Virtual Header, the 64-byte header on every SVL frame


GOLD
Generic Online Diagnostics, hardware fault detection


BUM
Broadcast, Unknown unicast and Multicast traffic


ROMMON
ROM Monitor, the boot environment that stores SVL and DAD settings


FIPS
Federal Information Processing Standards (140-2 crypto validation)


SPAN
Switched Port Analyzer, port mirroring


ECMP
Equal-Cost Multipath routing


ISSU
In-Service Software Upgrade


SDM
Switch Database Management template, the hardware table profile
